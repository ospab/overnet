# Журнал решений

## 2026-10-04 — overnet browser: перепакованный Mullvad Browser

**Решено:** браузер — **overnet browser**, официальная сборка Mullvad Browser,
перепакованная в GitHub Actions (`browser/repack.py`): наш брендинг, наши
настройки и политики, скрипт autoconfig, который запускает встроенный шлюз
overnet и встраивает overnet в интерфейс. Сам Gecko не пересобирается, поэтому
защита от отпечатков Tor Project остаётся нетронутой, а обновления дешёвые:
новый релиз Mullvad — новая перепаковка.

**Заменяет** п. 4 от 2026-06-23 (Chromium/Electron) и выбор 2026-10-01 «Mullvad
Browser с отдельным профилем»: профилем нельзя убрать брендинг Mullvad и
встроить overnet в интерфейс.

Обычные сайты (не .ov) в браузере по умолчанию заблокированы: прямое соединение
выдало бы IP пользователя рядом с его визитами на .ov.

## 2026-10-01 — Браузер: только Gecko

Chromium (а с ним и Electron) отпадает: браузер должен быть на движке Firefox с
защитой от отпечатков уровня Tor. Лёгкий путь: Mullvad Browser на компьютере,
позже — приложение на GeckoView для Android. Полный форк tor-browser-build пока
слишком тяжёл.

## 2026-06-23 — Упрощение: transport, обход блокировок, браузер

**Контекст:** ограниченные ресурсы (нет серверов в РФ, нет желания мучить CDN),
реальный опыт: Reality не даёт обхода whitelist, голый TCP лучше держит мобильные сети.

**Решено:**
1. **Reality / TLS-мимикрия / xhttp — убрать из боевого пути.** Несущий `Link` =
   обычный `TcpLink`. (`OstpLink`/`overnet-link-ostp` остаётся в репо как опция на
   будущее — transport-agnostic позволяет вернуть его одной строкой, но сейчас не используется.)
2. **Обход блокировок — НЕ задача overnet.** Сторонний VPN отдельно, overnet
   отдельно. overnet едет поверх любого IP-канала (домашний WiFi или коммерческий VPN).
   Цена/честность: если канал упадёт — overnet-поверх-интернета упадёт тоже; ответ на
   это — физический меш (фаза 3), но это долгосрочно.
3. **Сейчас — сеть на WiFi.** Мобильные устройства — позже.
4. ~~**Браузер — на базе Chromium (Electron), не Tauri и не форк.**~~
   *(заменено 2026-10-01 и 2026-10-04)* Развязка через **локальный HTTP-шлюз**:
   ядро overnet поднимает `127.0.0.1:PORT` (`overnet_node::web::run_gateway`),
   браузер вешает `overnet://` на него. Выбор браузера не вшит в ядро.

**Влияние на фазы:** фаза 1 теперь = «overnet поверх обычного интернета/VPN», без
собственной обфускации. Философия самодостаточности и неблокируемости остаётся целью
физического меша (фаза 3), не отменяется — откладывается.
