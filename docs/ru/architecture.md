# Архитектура overnet

*Версия 0.1 — 2026-06-23. Черновик. Многое ещё не решено — открытые вопросы помечены явно.*

---

## 0. Центральное решение

Всё держится на одном:

> **Ядро, не зависящее от транспорта + криптографическая адресация +
> децентрализованная маршрутизация.**

Если это сделать правильно, всё остальное (этапы, среды, приложения) становится
заменяемой деталью. Если неправильно — проект мёртв, каким бы хорошим ни был
шифр.

## 1. Слои

overnet сознательно **не выбрасывает** идею слоёв (OSI и коммутация пакетов —
хорошая инженерия). Он заменяет только то, что делает классический стек
блокируемым: централизованную адресацию (RIR), централизованную маршрутизацию
(BGP) и зависимость от лицензируемой среды.

```
┌──────────────────────────────────────────────┐
│  Приложения (мессенджер, файлы, публикации)  │
├──────────────────────────────────────────────┤
│  Сессии / потоки (надёжная доставка)         │
├──────────────────────────────────────────────┤
│  Луковая маршрутизация                       │  ← ядро
│  Адрес = f(открытый ключ)                    │
├──────────────────────────────────────────────┤
│  Абстракция транспорта (Link = ребро графа)  │  ← ключ к живучести
├───────────┬──────────┬──────────┬────────────┤
│ TCP /     │ Wi-Fi    │ LoRa /   │ Bluetooth /│  ← заменяемые среды
│ ostp      │ антенна  │ радио    │ флешка     │
└───────────┴──────────┴──────────┴────────────┘
```

### 1.1. Абстракция транспорта (Link)

Самая важная и самая тестируемая часть. `Link` — двунаправленный канал доставки
кадров между двумя соседними узлами. Ядру всё равно, что под ним:

- **Туннель TCP / ostp** — ребро через интернет (этап 1, с переиспользованием `ostp`).
- **Wi-Fi точка-точка** (направленная антенна) — физическое ребро (этап 3).
- **LoRa / пакетное радио** — дальнее узкополосное ребро (текст, store-and-forward).
- **Bluetooth / Wi-Fi Direct** — локальные рёбра между телефонами без интернета.
- **Sneakernet** — асинхронное ребро (флешка / QR), store-and-forward.

Контракт `Link` (черновик):
```
trait Link {
    fn send(frame: &[u8]) -> Result<()>;       // отправить кадр соседу
    fn recv() -> Result<Vec<u8>>;               // принять кадр от соседа
    fn mtu() -> usize;                          // максимальный размер кадра
    fn properties() -> LinkProps;               // задержка, полоса, надёжность, направленность
}
```
`properties()` нужен маршрутизации, чтобы выбирать путь (видео по LoRa не
протолкнуть).

**Открытый вопрос:** один формат кадра для всех сред или адаптеры для каждой.
Вероятно, адаптеры с общим внутренним пакетом.

### 1.2. Адресация

Адрес узла выводится из его долговременного открытого ключа (например, хеш
ключа Ed25519/X25519). Свойства:

- **Самоназначаемый** — узел создаёт ключ и получает адрес. Без реестра.
- **Самоудостоверяющий** — зная адрес, знаешь, чей за ним ключ; без закрытого
  ключа выдать себя за узел нельзя.
- **Не отзывается централизованно** — нет органа, который может «забанить» адрес.

**Открытый вопрос:** как сделать человекочитаемые имена (petname / web-of-trust)
без централизованного DNS. Ответ v0.2: самоудостоверяющие адреса `.ov` плюс
регистратор, записи которого клиент проверяет, — см. [naming.md](naming.md) и
[running.md](running.md).

### 1.3. Луковая маршрутизация (ядро приватности)

Каждый хоп знает только предыдущего и следующего — никогда всю картину. Это
**луковая маршрутизация**, и нужна строгая, проверенная в бою версия
(**Sphinx**), а не наивная «попробовать расшифровать заголовок → не вышло →
разослать всем» (это ведёт к флуду и не масштабируется, а RSA на каждом хопе
убивает скорость).

Механика Sphinx вкратце: источник кладёт в заголовок эфемерный открытый ключ;
нужный хоп детерминированно выводит ключ своего слоя **одним ECDH X25519**,
снимает свой слой, читает явное «следующий хоп = X» и отправляет дальше одному
получателю. Пакеты фиксированной длины (длина маршрута не утекает), защита от
повторов. Подробная модель пакета и криптографии — в отдельном документе
`packet-crypto.md`.

> **Статус v0.2:** вместо этого цепи строятся как в Tor — рукопожатие ntor на
> каждом хопе, ячейки фиксированной длины по 1024 байта, слой ChaCha20 на хоп,
> потоки с окнами SENDME. Sphinx остаётся целью для асинхронного трафика /
> store-and-forward. См. [running.md](running.md).

**Выходы необязательны.** По умолчанию адресат — узел overnet, а не сайт в
обычном интернете, поэтому классических проблем выходных узлов (злоупотребления,
блокировки, юридические претензии к выходу) не возникает. Выходы в обычный
интернет — только как добровольная роль узла, по умолчанию выключенная и явно
помеченная; самодостаточная часть сети от них не зависит.

## 2. Топология доверия и выбор входов (guard)

Открытое членство уязвимо к атаке Sybil: государство заливает сеть тысячами
своих узлов, чтобы деанонимизировать пользователей и ломать маршруты. Создать
идентичность у нас **ничего не стоит** (адрес = f(ключ)), поэтому «сотня
враждебных узлов» — не гипотеза, а норма.

**Якорь доверия бывает только трёх видов — четвёртой двери нет:**
центральный орган (отвергнут — его можно захватить или принудить), дефицитный
ресурс (PoW / stake) или социальный граф (F2F / web-of-trust). Поведенческие
эвристики («узел стабильно себя ведёт — значит, доверяем») — **НЕ** четвёртая
дверь, а подменяемая замена: терпеливое государство сделает свои узлы
стабильнее и старше узлов реальных людей, и эвристика в итоге выберет **именно
противника**.

### Решение (принято 2026-06-23)

**База (для всех участников):**
- **луковая маршрутизация со свойствами mixnet** (задержки + покрывающий трафик
  + выравнивание) против временной корреляции (см. глоссарий, threat-model §4);
- **личные, скрытые входы** — каждый участник выбирает СВОИ точки входа и не
  раскрывает их. Общий публичный список входов — это список целей (ошибка, от
  которой страдает открытый список релеев Tor, — отсюда «мосты»);
- **разнообразие пути** — никогда не брать два хопа из одной подсети / AS /
  у одного оператора;
- **дорогие идентичности (PoW)** — поднять цену Sybil с «бесплатно» до
  «дорого».

**Локальное наблюдение за поведением — только защита, никогда не присвоение.**
Клиент может локально и негласно **отказаться** от входа, который ведёт себя
подозрительно (рвёт цепи, зондирует). Но у него **нет** права присваивать кому-то
общесетевой статус доверия и рассылать его: самоаттестация бесполезна (лгут
как раз злодеи), а голосование подделывается сивиллами.

**Необязательный жёсткий уровень — F2F / web-of-trust** для участников с высоким
риском: прямые связи только со знакомыми. Плюсы: устойчивость к внедрению,
идеальное совпадение с физической mesh-сетью, естественное сочетание с
«участник = узел».

Итог: анонимность **плавно деградирует** по мере роста доли противника, а не
падает до нуля на первой сотне враждебных узлов. Полной устойчивости к
глобальному коррелятору мы не обещаем (см. threat-model §4).

**Открытый вопрос (большой):** граница между открытым ростом (база) и F2F-ядром
(жёсткий уровень). Гибрид пока не формализован.

## 3. Этапы развёртывания

Одна кодовая база, три этапа сред:

**Этап 1 — Оверлей (сегодня).**
Поверх интернета, под видом разрешённого трафика. Интернет-`Link` оборачивает
`ostp_core::protocol::ProtocolMachine` (Noise + выравнивание + обфускация
заголовков; Reality из ostp убран в 0.4.0) — переиспользуется, а не
переписывается (overnet зависит от `ostp-core` по пути). Даёт пользу и
пользователей прямо сейчас и обкатывает ядро. Луковые слои overnet — сверху.

**Этап 2 — P2P-сеть (самодостаточный даркнет).**
Луковая маршрутизация, топология F2F, обход NAT / hole punching для прямого p2p
через интернет. Сеть становится логически самодостаточной: клиенты overnet
общаются с клиентами overnet, не завися от выхода в обычный интернет.

**Этап 3 — Физика (эндшпиль).**
Своя среда там, где позволяет плотность: направленные Wi-Fi-антенны, LoRa,
оптика. Тот же стек поверх физических `Link`. Единственное, что DPI не может
заблокировать в принципе, — ценой физической обнаружимости (см. threat-model).

## 4. Граница «шифровать или маскировать»

Жёсткое следствие, которое надо всегда держать в голове:

- **В своей сети (этапы 2–3)** все пересылающие узлы наши, поэтому пакет
  шифруется целиком; открытой остаётся только локальная адресация для соседнего
  физического хопа (глобальному наблюдателю она ничего не говорит).
- **Поверх чужого интернета (этап 1)** внешний IP-заголовок **нельзя**
  зашифровать — по нему маршрутизируют чужие маршрутизаторы. Там мы не прячем
  конверт, а **маскируем** его под разрешённый трафик (ostp). Всё ценное — внутри.

И отдельно: **одно шифрование DPI не побеждает.** Высокоэнтропийный «мусор без
рукопожатия TLS» — вопиющая аномалия, которую режим белых списков отбросит по
форме, не читая. Поэтому нужна либо мимикрия (этап 1), либо своя среда (этап 3),
плюс защита от анализа трафика (выравнивание до фиксированной длины,
перемешивание — территория mixnet: Loopix / Nym).

## 5. Открытые проблемы (честно)

Протокол — простая часть. Убивают вот это:

1. **Масштабируемость маршрутизации.** Плоская mesh-сеть не вынесет миллионы
   узлов (это показал cjdns). Нужна иерархия / DHT — не решено.
2. **Sybil / доверие.** См. §2. F2F помогает, но ломает открытый рост.
3. **Стимулы / участие.** «Участник = узел» опирается на идеологию. Что будет,
   когда энтузиазм угаснет, — открытый вопрос. Токены пока не рассматриваем
   (регуляторная и моральная ловушка).
4. **Физическая обнаружимость (этап 3).** Радио можно запеленговать.
   Неблокируемость сети покупается физическим риском оператора.
5. **Обход NAT (этапы 1–2).** NAT операторского уровня мешает прямому p2p;
   нужны hole punching и ретрансляторы.

## 6. На чьих плечах стоим (изучить, прежде чем писать своё)

- **Reticulum (RNS)** — криптостек без привязки к транспорту поверх любой среды;
  ближе всего к нашему видению, изучать первым.
- **Yggdrasil** — криптоадреса из ключей + самомаршрутизация.
- **Sphinx** (Данезис и Голдберг) — формат лукового пакета.
- **Tor ntor**, **Noise Framework**, **WireGuard** — как делать рукопожатия, не
  изобретая криптографию.
- **Briar** — F2F + несколько транспортов (Tor / Bluetooth / Wi-Fi Direct),
  офлайн.
- **Loopix / Nym** — защита метаданных от анализа трафика.

Возможно, наш вклад — не новый стек, а слой приватности / стимулов / UX поверх
существующего. Решим это, пожив неделю с Reticulum и Yggdrasil.
