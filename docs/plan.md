# Итоговый план

*Версия 0.1 — 2026-06-23. Зафиксированные решения и порядок сборки. От «доки» к коду.*

---

## Стек (зафиксировано)

**Rust + tokio**, переиспользуем крипто-крейты `ostp` один-в-один. Ноль трения с
фазой 1, memory-safety для сетевого кода, примитивы уже проверены в проде `ostp`.

Крипто (как в `ostp`, своё НЕ катаем): `snow` (Noise), `x25519-dalek`,
`chacha20poly1305` (AEAD), `ed25519-dalek` (личность/подписи).

**Лицензия: `AGPL-3.0-only`** — совместимо с `ostp` (AGPLv3), копилефт с сетевым
пунктом §13 держит форки и сервисы открытыми (см. distribution.md).

## Переиспользование ostp (решено 2026-06-23)

overnet = **отдельный репо**, зависит от `ostp-core` через path
(`ostp-core = { path = "../../ostp/ostp-core" }`). Проверено: собирается
кросс-репно. Низкий/средний уровень **берём из ostp, НЕ переписываем**:

- `crypto::reality` — Reality/TLS-мимикрия (моат против ТСПУ);
- `protocol::ProtocolMachine` — надёжный Noise+PSK туннель (sans-io) + паддинг +
  congestion + переупорядочивание;
- `framing` (`PaddingStrategy`/`AdaptivePadder`) — защита от анализа трафика;
- `dnstt`/`dns` — DNS-туннель как ещё один носитель.

Чего в ostp **нет** (это и есть новая работа overnet, аддитивно сверху):
onion-маршрутизация, криптоадресация, меш-роутинг, transport-agnostic `Link`.
`ostp::relay` — это SOCKS-подобный прокси-выход (точка-точка), **не** onion.

**Слои hop-шифрования:** интернет-`Link` = туннель ostp (Reality+Noise встроены);
«голый» `Link` (LoRa/Bluetooth, без своего шифра) = bare-Noise из
`overnet-core::session`. Onion-слои overnet — поверх любого `Link`, end-to-end.

## Решения и компромиссы

| Компонент | Решение | Компромисс |
|---|---|---|
| Язык/рантайм | Rust + tokio | — |
| Криптопримитивы | snow + x25519-dalek + chacha20poly1305 + ed25519-dalek | не изобретаем |
| Личность/адрес | ed25519 → `addr = sha256(pubkey)` | сейчас hex, base32+checksum позже |
| Транспорт | `trait Link` | ядро, без компромисса |
| Фаза-1 транспорт | обёртка туннеля `ostp` как `Link` | переиспользуем Reality, не пишем заново |
| Приватность | onion, source-routed, 3 хопа | MVP: слои + per-hop X25519; строгий Sphinx — v2 |
| Mixnet | hook есть, в MVP выключен | форвард-совместимо, не тормозим запуск |
| Доверие/Sybil | open + vouched, MVP = только open | ваучеры на ed25519 добавятся без передизайна; PoW/анон-credentials позже |
| Именование | криптоадрес + petnames | глобальные/блокчейн-имена — нет |
| Bootstrap | инвайт/QR + вшитые ноды | — |
| Репозиторий | open source (AGPL), старт — локальный git, `private/` исключён | зеркала/подпись релизов после MVP |

**Философия компромиссов:** тонкий сквозной срез на сильных примитивах, простейшей
топологией; усиление инкрементально, не закрашивая путь к усложнению.

## MVP — «ходячий скелет» (v0.0.1)

Три узла **A → R → B**, у каждого ed25519-личность и криптоадрес. A заворачивает
сообщение в onion (2 слоя), шлёт через релей R. **R видит только соседей — не
содержимое и не адресата.** B снимает последний слой. Транспорт под этим — TCP
(dev) либо туннель `ostp` (фаза 1), и подмена транспорта ничего не меняет выше.

Доказывает разом: transport-agnostic ядро + криптоадреса + onion + интеграцию с `ostp`.

## Раскладка воркспейса (плоская, как в ostp)

```
overnet/
  Cargo.toml          # workspace
  overnet-core/       # Link, Identity, Address (+ packet, onion)
  overnet-link-tcp/   # Link поверх TCP
  overnet-link-ostp/  # обёртка туннеля ostp (фаза 1)
  overnet-node/       # рантайм узла
  overnet-cli/        # dev-харнесс
```

## Порядок сборки (вехи)

- [x] **Шаг 0** — скелет воркспейса + `overnet-core`: `Identity` (ed25519),
      `Address` (= sha256(pubkey)), `trait Link`, loopback-`Link` с тестом.
- [x] **Веха 1** — `overnet-link-tcp`: length-framed TCP `Link`. Кадр ходит A↔B (тест).
- [x] **Веха 2** — Noise-сессия (`snow`) поверх `Link` + эхо клиент↔сервер (тесты).
- [~] **Веха 3** — onion: `overnet-core::onion` — построение/снятие слоёв
      (per-hop X25519 + AEAD), релей не видит payload (3 теста зелёные). **Осталось:**
      маршрутизировать onion через узлы по `Link` (A→R→B вживую) = **MVP**.
- [ ] **Веха 4** — `overnet-link-ostp`: обернуть `ostp::ProtocolMachine` → фаза 1.
- [ ] **Веха 5** — обнаружение соседей, маршрутизация → усиление (Sphinx, mixnet, рефералы).

## Что НЕ делаем на старте

Свои криптопримитивы; глобальный namespace/блокчейн-имена; токены; mixnet-задержки;
PoW и анонимные удостоверения; оптимизацию под масштаб до рабочего ядра.
