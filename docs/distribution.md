# Распространение: код и приложение

*Версия 0.1 — 2026-06-23. Два разных вопроса, которые часто путают: где лежит
ИСХОДНИК и как приложение попадает к ЛЮДЯМ.*

---

## Часть 1. Исходный код — открытый

**Решение: код и протокол — open source. Для такого проекта это не обсуждается.**

Почему:

- **Принцип Керкгоффса** — система должна быть стойкой, даже когда противник знает
  про неё всё. Стойкость в ключах, не в тайне дизайна. «Безопасность через
  скрытость» — известный провал.
- **Доверие = аудируемость.** Целевая аудитория (активисты, журналисты,
  технически грамотные) не запустит анти-цензурный инструмент, который нельзя
  проверить. Закрытый код в этой сфере — красный флаг. Tor, Signal, WireGuard,
  Briar — все открыты.
- **Та самая слава.** Репутация уровня Bellard/djb строится только в открытую.
  Закрытым кодом в «тот список» не попадают.
- **Живучесть.** Открытый код нельзя убить, убрав одного человека: форки выживут.

### Где хостить

- **Зеркала, а не одна площадка.** GitHub в РФ уже тормозили/блокировали — он не
  может быть единственным. Держим зеркала: **Codeberg** (некоммерческий, на базе
  Forgejo), **GitLab**, опционально собственный Forgejo. Пуш во все сразу.
- **Подпись релизов** (GPG/minisign) — чтобы пользователь проверил, что бинарь от
  нас.
- **Воспроизводимые сборки (reproducible builds)** — чтобы любой мог собрать из
  исходника и убедиться, что бинарь совпадает и в него не вшит бэкдор. Цель, к
  которой идём; для анти-цензурного проекта почти обязательна.

### Личность автора — твоё решение, не моё

Публичный репо привязывает проект к твоему GitHub/имени. Для проекта, бьющего по
ТСПУ, это **личный риск** (см. `private/risk-and-opsec.md`). Псевдонимное
сопровождение — законный и распространённый выбор (Bitcoin начинался как Сатоши,
многие privacy-проекты — под псевдонимами). Открытость **кода** и публичность
**твоего имени** — разные вещи; можно открыть первое, не раскрывая второе.
Это твой осознанный выбор по порогу риска, прими его до первого пуша.

## Часть 2. Доставка приложения людям — отдельная задача

Открытый репозиторий ≠ канал доставки. Тут другая логика и другая боль.

### Проблема упреждающего распространения

Инструмент против блокировок нужно раздать **до** блэкаута. После закрытия границы
магазины приложений и GitHub недоступны — скачать уже негде. Значит, распространять
надо, **пока интернет открыт**, и закладывать офлайн-каналы.

### Каналы доставки

- **F-Droid / собственный репозиторий APK** — для Android, без Google. Сайдлоад.
- **Прямой APK с зеркал + подпись** — на случай блокировки сторов.
- **P2P-передача установщика** — приложение умеет **раздавать само себя** соседу по
  Bluetooth/WiFi Direct (как Briar, Bridgefy). Это и есть распространение, которое
  переживает блэкаут: один человек с приложением «заражает» соседей офлайн.
- **iOS** — самое узкое место (Apple запрещает сайдлоад в большинстве регионов);
  возможно, позже и через сложности. Не приоритет старта.

### Рост = приглашения (и это же якорь доверия)

Сарафан через инвайты — одновременно модель роста и Sybil-защита (см. naming.md,
architecture §2). Один механизм решает обе задачи: приглашённый приходит уже
«представленным» доверенным участником.

## Громкость vs безопасность

Открытость кода полезна. Громкая реклама «неубиваемой сети» — рисует мишень на
авторе и ранних участниках, а в фазе 3 (радио) добавляет физический риск. Это в
прямом конфликте, и его надо держать в голове. Реалистичный путь — не вирусность, а
**репутация среди тех, у кого уже есть боль** (см. `private/go-to-market.md`).
