# Запуск overnet v0.2: цепи, сервисы .ov, браузер

*2026-10-01. Как поднять сеть, опубликовать сайт и смотреть его в браузере;
как overnet работает вместе с ostp.*

---

## Что изменилось в v0.2

Сеть построена по образцу Tor, но без его инфраструктуры:

- **Цепи.** Клиент строит цепь из трёх релеев: CREATE к первому, EXTEND дальше.
  С каждым хопом — рукопожатие ntor (`overnet-core/src/ntor.rs`): только владелец
  ключа релея может ответить, а релей ничего не узнаёт о клиенте.
- **Ячейки фиксированной длины** (1024 байта, `cell.rs`), слой ChaCha20 на каждый
  хоп. Каждый хоп видит только соседей; содержимое — только адресат.
- **Потоки** внутри цепи (BEGIN/DATA/END) с окном SENDME: TCP, HTTP, WebSocket —
  что угодно.
- **Сервисы .ov** — через точки входа и склейку цепей (как onion-сервисы Tor):
  ни клиент, ни сервис не знают адресов друг друга. Точки входа вычисляются из
  ключа сервиса и каталога, публиковать дескрипторы не нужно.
- **Адрес сервиса** — 56 символов + `.ov` (ключ ed25519 + checksum), подделать
  нельзя. Короткие имена: зарезервированные вшиты в клиент, остальные — у
  регистратора `name.ov`, причём клиент проверяет подпись владельца имени.
- **Клиент не ходит к bootstrap-серверу.** Каталог релеев он берёт у релея через
  цепь. Bootstrap знает только релеи (они публичны по природе).

Старый стек «запрос/ответ» и его команды живут в `overnet legacy …` — на нём ещё
работает Tauri-приложение. Уязвимость старого `REGISTER` (любой мог назваться
чужим ключом) в v0.2 не существует: точку входа сервис занимает подписью,
привязанной к конкретной цепи.

## Роли и команды

| Кто | Команда | Что делает |
|-----|---------|------------|
| bootstrap | `overnet bootstrap 0.0.0.0:8080` | каталог релеев (только релеи) |
| релей | `overnet relay --bootstrap B:8080 --advertise IP:4040` | пересылает ячейки; печатает строку для `relays` |
| выход | `overnet relay … --exit direct` или `--exit socks5://127.0.0.1:9151` | выпускает в интернет; **по умолчанию выключен** |
| сайт | `overnet service --key shop.key --port 80=127.0.0.1:8080` | любой локальный HTTP-сервер становится сайтом .ov |
| служебный сайт | `overnet site name\|search\|files\|mail` | регистратор, поиск, файлы, почта |
| клиент | `overnet gateway` | SOCKS5 на 127.0.0.1:9150 |
| браузер | `overnet browser` | Mullvad Browser с профилем overnet |

Конфиг (`config.json`, флаг `--config`):

```json
{
  "token": "",
  "relays": ["<pubkey hex>@1.2.3.4:4040", "<pubkey hex>@5.6.7.8:4040"],
  "reserved": {
    "name.ov":   "<адрес>.ov",
    "search.ov": "<адрес>.ov",
    "mail.ov":   "<адрес>.ov",
    "files.ov":  "<адрес>.ov"
  },
  "gateway": { "listen": "127.0.0.1:9150", "clearnet": "direct" },
  "relay":   { "listen": "0.0.0.0:4040", "bootstrap": "1.2.3.4:8080", "exit": "off" },
  "browser": { "path": "", "gateway": "auto" }
}
```

Bootstrap-серверу стоит задать `node_ttl_secs` (например 120), чтобы выключенные
релеи пропадали из каталога. Релеи v0.1 (`overnet legacy relay`) ячеек не
понимают — не смешивайте их с v0.2 в одном каталоге.

`gateway.clearnet` — куда шлюз отправляет всё, что не `.ov`: `direct` (как без
шлюза, ваш IP виден сайтам), `exit` (через выход overnet) или `block`.

## Попробовать на одной машине

```
overnet demo        # 5 релеев, name/search/files/mail, шлюз на 127.0.0.1:9150
overnet browser     # в другом окне
```

Ключи демо-сайтов хранятся в `%LOCALAPPDATA%\overnet\demo` (Linux —
`~/.local/share/overnet/demo`), адреса между запусками не меняются.

## Опубликовать свой сайт

```
overnet keygen shop.key                          # печатает адрес .ov
overnet service --key shop.key --port 80=127.0.0.1:8080
overnet name-sign shop.ov --key shop.key         # вставить на http://name.ov/
```

Сайту не нужны белый IP, домен и сертификат: сервис сам подключается к сети.

## Браузер

`overnet browser` запускает **Mullvad Browser** (Firefox ESR с защитой от
отпечатков от Tor Project, без Tor) с отдельным профилем: тёмная тема overnet,
SOCKS5 с удалённым DNS (иначе `.ov` утёк бы в системный DNS), выключенный DoH,
`search.ov` как домашняя страница, служебные сайты `.ov` в списке безопасных
контекстов (иначе почта не сможет шифровать в браузере). Сайты `.ov` открываются
по `http://` — шифрует сама сеть; обычные сайты браузер по-прежнему переводит на
https (режим HTTPS-first).

**Детект ostp.** Перед запуском браузер резолвит `name.ov` системным DNS. Если
ответ — фиктивный адрес ostp (`198.18.0.0/15`), значит работает VPN ostp в
режиме TUN, а его сервер выводит `.ov` в overnet. Тогда браузер запускается без
прокси. Иначе поднимается локальный шлюз (или берётся уже запущенный). Режим
меняется флагом `--gateway auto|always|never`. `always` полезен, если не хотите,
чтобы сервер ostp видел, какие сайты `.ov` вы открываете.

Если Mullvad Browser не найден, запускается Firefox с предупреждением: у него
нет защиты от отпечатков. Путь можно задать в `browser.path` или в
`OVERNET_BROWSER`.

**Телефоны.** Mullvad Browser есть только для Windows, macOS и Linux. На Android
и iOS overnet работает через приложение ostp в режиме VPN с сервером, где
включён `overnet.entry`: тогда `.ov` открывается в любом браузере. Почта
`mail.ov` там пока не работает, потому что мобильные браузеры не считают
`http://mail.ov` безопасным контекстом. В сборках Firefox для Android с
`about:config` (например IronFox) это лечится той же настройкой
`dom.securecontext.allowlist`.

## Вместе с ostp

На сервере ostp рядом с ним запускаются шлюз и (по желанию) релей-выход overnet:

```
overnet gateway                                    # 127.0.0.1:9150 — сюда ostp шлёт .ov
overnet relay --exit socks5://127.0.0.1:9151 …     # выход через правила ostp
```

а в конфиге ostp:

```json
"overnet": { "enabled": true, "entry": true, "gateway": "127.0.0.1:9150",
             "exit": true, "exit_listen": "127.0.0.1:9151" }
```

`entry` — клиенты ostp открывают `.ov` в любом браузере, ничего не настраивая.
`exit` — трафик overnet выходит в интернет по правилам этого сервера (outbound,
`bind_ip`, блок-листы); сам сервер и частные сети закрыты. Подробности — в
`docs/*/server.md` ostp.

## Честно о границах

- **Линк между узлами пока не шифруется.** Содержимое ячеек зашифровано
  слоями, но номера цепей и команды ячеек видны на проводе. Это закроет
  транспорт ostp (`overnet-link-ostp`) — следующий шаг.
- **Анонимность зависит от размера сети.** В сети из пяти релеев против
  наблюдателя, который видит весь трафик, она слабая. В маленькой сети цепи
  короче трёх хопов.
- **Нет защиты от Sybil.** Любой может поднять много релеев. Вход («guard»)
  клиент держит один на всё время работы, но политики guard'ов Tor пока нет.
- **Точка входа видит**, что к сервису X пришёл кто-то, и когда. Кто именно и
  где сервис — нет.
- **Регистратор может отказать** в имени или «забыть» его, но подменить адрес
  не может: клиент проверяет подпись владельца.
- **Почта:** сервер видит, в какой ящик и когда пришло письмо и его размер.
  Отправитель внутри письма не подписан.
